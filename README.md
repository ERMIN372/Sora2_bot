# Sora2_bot

Sora2_bot — это Telegram-бот, который подключается к API генерации видео Gemini
Veo и изображений через Google Gemini. Он управляет заданиями пользователей и
обрабатывает платежи в Telegram Stars и через YooKassa.

## Предварительные требования

- Python версии 3.10 или новее.
- Токен Telegram-бота, полученный у [@BotFather](https://t.me/BotFather).
- Ключ Gemini (`GOOGLE_API_KEY` или `GEMINI_API_KEY`) с доступом к моделям Veo и
  Image.
- (Опционально для генерации изображений) ключ Gemini (`GOOGLE_API_KEY` или `GEMINI_API_KEY`).
- (Необязательно) Redis, если вы планируете использовать собственное хранилище
  конечного автомата (FSM) или бэкенд ограничения скорости для Aiogram.

## Установка

1. **Клонируйте репозиторий**
   ```bash
   git clone https://github.com/your-org/Sora2_bot.git
   cd Sora2_bot
   ```
2. **Создайте и активируйте виртуальное окружение**
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # В Windows используйте: .venv\Scripts\activate
   ```
3. **Установите зависимости**
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```
4. **(Необязательно) Установите инструменты разработки** — например, `black`,
   `ruff` или `pytest`, если планируете расширять бота и добавлять тесты.

### Google Sheets setup

1. Создайте пустую Google-таблицу и скопируйте её идентификатор из URL в
   переменную `GOOGLE_SHEET_ID`.
2. В консоли Google Cloud создайте сервис-аккаунт, скачайте JSON-ключ и
   закодируйте содержимое файла в Base64 (например, `base64 <key.json>`).
   Полученную строку поместите в переменную `GOOGLE_SA_JSON_BASE64`. Этого
   достаточно для доступа к Google Sheets с правами «Редактор».
3. Откройте созданную таблицу и поделитесь ею с почтовым адресом
   сервис-аккаунта (`client_email` из JSON), предоставив права «Редактор».
4. При необходимости переименуйте листы и обновите переменные
   `GS_USERS_SHEET`, `GS_PAYMENTS_SHEET`, `GS_JOBS_SHEET`. Если оставить их
   пустыми, будут использованы значения по умолчанию (`users`, `payments`,
   `jobs`).

**Советы**

- Храните секреты, такие как `TELEGRAM_BOT_TOKEN` и `GEMINI_API_KEY`, в менеджере секретов
  в продакшене и передавайте их приложению в виде переменных окружения во время
  выполнения.
- При деплое на платформы, которые не поддерживают `.env` напрямую, экспортируйте
  переменные или настройте их через параметры окружения платформы.
- Используйте отдельные Google-таблицы или хотя бы отдельные листы для
  разработки, стейджинга и продакшена, чтобы избежать конфликтов данных.

### Настройка YooKassa

1. Получите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в кабинете YooKassa и
   включите тестовый режим, если отлаживаете оплату (`YOOKASSA_TEST_MODE=true`).
   Секретный ключ обязателен для валидации заголовка `X-YooKassa-Signature`
   (HMAC-SHA256 тела запроса); при неверной подписи вебхук будет отклонён с 401.
2. Укажите публичный HTTPS-домен в `PUBLIC_BASE_URL`. На нём должен быть настроен
   проброс трафика (reverse proxy) к локальному порту FastAPI `PORT`
   (по умолчанию 8080).
3. Добавьте вебхук в кабинете YooKassa, указав URL вида
   `https://your.domain{YOOKASSA_WEBHOOK_PATH}`.
4. Для страницы возврата пользователю настройте redirect на
   `https://your.domain{YOOKASSA_RETURN_PATH}` — она сообщает статус платежа.
5. При необходимости включите отправку чеков (`YOOKASSA_SEND_RECEIPTS=true`) и
   настройте контактные данные покупателя в коде (по умолчанию email-заглушка).
6. (Опционально) Укажите `SUBSCRIPTION_CHAT_ID`, чтобы активировать бонус за
   подписку на канал после первого платежа (Stars или YooKassa).

## Запуск бота

После настройки переменных окружения запустите бота командой:

```bash
python main.py
```

Переменная `BOT_MODE` задаёт режим запуска:

- `polling` — бот удаляет существующий вебхук и запускает long polling, одновременно
  оставляя FastAPI-сервер в фоне для вебхуков YooKassa и проверки `/healthz`.
- `webhook` — бот устанавливает вебхук и запускает единый FastAPI-сервер (Telegram,
  YooKassa и `/healthz`). Long polling не используется.

CLI-флаг `--mode` переопределяет значение `BOT_MODE`, что удобно для локального
тестирования. Примеры:

```bash
python main.py --mode polling
python main.py --mode webhook
```

Процедура запуска автоматически выполняет следующие шаги:

1. Загружает конфигурацию из окружения.
2. Подключается к Google Sheets (создаёт листы и перестраивает индексы при необходимости).
3. Создаёт клиентов Gemini (включая Veo для видео) и воркеров очереди фоновых
   заданий.
4. В зависимости от режима либо удаляет вебхук и запускает polling, либо устанавливает
   вебхук и ожидает входящих HTTP-запросов.

Нажмите `Ctrl+C`, чтобы остановить процесс. При завершении работы очередь
дренируется, сетевые сессии закрываются, вебхук Telegram удаляется, а соединения с
базой данных освобождаются.

### Ограничение скорости команд

- Если задан `AIROGRAM_REDIS_URL`, для всех пользователей включается Redis-бэкенд
  ограничения скорости с ключами `rate_limit:{user_id}:{command}`.
- По умолчанию ограничиваются команды: `/video_create` и `/video_remix` — 5 запросов
  в 60 секунд, `/video_get` — 3 запроса в 60 секунд, `/video_models` и `/models` —
  10 запросов в 60 секунд.
- Правила можно переопределить переменной `RATE_LIMITS`, указав пары
  `команда:лимит:период` через запятую, например `video_create:3:30,models:5:60`.

Если при опросе Veo приходит `403 PERMISSION_DENIED` для операции
`veo-3.0-generate-001`, задача помечается как `failed` с причиной "operation not
accessible" и больше не ретраится — проверьте доступ к операции или используемый
API-ключ.

## OpenAI Video API (Sora 2)

### Возможности

Бот поддерживает полный цикл работы с OpenAI Video API: создание роликов (`/video`),
ремиксы по готовому видео (`/video_remix`), просмотр списка заданий (`/video_list`),
получение подробной информации (`/video_info`) и ручное скачивание готового контента
администратором (`/video_get`).
Все команды используют общий клиент `OpenAIVideoClient`, который автоматически
учитывает выбранную модель, размер кадра и стоимость в кредитах. 【F:handlers.py†L3110-L3374】【F:handlers.py†L3377-L3560】

Для отображения доступных моделей предусмотрена команда `/video_models`, а общая
команда `/models` объединяет список Gemini и Sora 2. Встроенная диагностика
`/diag_openai_video` проверяет подключение, скорость ответа API и актуальные модели. 【F:handlers.py†L3080-L3107】【F:handlers.py†L3563-L3695】

### Конфигурация

При старте приложения создаются клиенты Sora 2 (через Responses API) и новый
клиент OpenAI Video API; они регистрируются в пуле провайдеров и доступны под
именами `openai-video` и `openai-video-api`. 【F:main.py†L111-L132】

Ключевые переменные окружения для Sora 2:

- `SORA_API_KEY` или `OPENAI_API_KEY` — токен с доступом к Video API; без него клиент не инициализируется. 【F:providers/openai_video.py†L37-L51】
- `SORA_MODEL_VIDEO` — целевая модель (по умолчанию `sora-2`). 【F:config.py†L188-L199】
- `OPENAI_API_BASE`, `OPENAI_API_VERSION_VIDEO` и `OPENAI_BETA_HEADER` — позволяют переключиться на собственный эндпоинт, указать версию API и заголовок беты (`video=1`). 【F:providers/openai_video.py†L40-L57】
- `PROVIDER_TIMEOUT_S` — общий тайм-аут HTTP-клиента, который применяется к запросам OpenAI Video API. 【F:config.py†L213-L225】

### Ограничения и доступ

- Клиент OpenAI Video API требует действующий ключ и активированное бета-подключение (заголовок `OpenAI-Beta: video=1`). Без него запросы вернут ошибку авторизации. 【F:providers/openai_video.py†L40-L54】【F:providers/openai_video.py†L121-L129】
- Значение `sora` больше не поддерживается: используйте модель семейства `sora-2` или ту, что опубликована для вашего аккаунта. 【F:config.py†L191-L195】
- Для ручной диагностики добавлена команда `/video_get`, которая скачивает готовый
  файл напрямую по `video_id` и отправляет его администратору. 【F:handlers.py†L3538-L3604】
- Скорость обработки ограничена глобальными лимитами OpenAI и параметром `sora_requests_per_minute`; при превышении лимита стоит уменьшить частоту команд. 【F:config.py†L196-L203】

Если доступ к бете ещё не открыт, подайте заявку в кабинете OpenAI или через менеджера
поддержки и дождитесь включения Sora 2 для вашего ключа. После активации выполните
`/diag_openai_video`, чтобы проверить соединение и список моделей. 【F:handlers.py†L3563-L3606】

Чтобы запускать бота в фоне в продакшене, используйте менеджер процессов вроде
`systemd`, `supervisord`, Docker или систему оркестрации контейнеров.

## Логирование и наблюдаемость

- Логирование настраивается глобально через `logging.basicConfig(level=logging.INFO)`
  и выводится в стандартный вывод. Сохраняйте вывод процесса в рантайме
  контейнера или менеджере процессов для долгосрочного хранения.
- Очередь заданий и взаимодействия с Gemini API записывают информационные события
  для успешных переходов, предупреждения для ошибок, подлежащих повтору, и
  трассировки стека при неожиданных исключениях.
- Чтобы изменить уровень подробности логов, скорректируйте вызов
  `logging.basicConfig` в `main.py` или оберните бота в небольшой стартовый
  скрипт, который настроит логирование перед импортом `main`.

## Эксплуатационные инструкции

### Проверка подписки и кредитов

1. Используйте команду `/balance` в Telegram, чтобы проверить остаток кредитов
   пользователя.
2. Откройте лист `payments` в Google Sheets и убедитесь, что последний платёж
   Telegram Stars записан с подходящими идентификаторами транзакций.
3. Если баланс кажется некорректным, повторно запустите `successful_payment_handler`,
   переслав боту оригинальный чек Telegram, одновременно наблюдая логи
   активности `TelegramStarPaymentProcessor`.
4. Убедитесь, что пользователь не превысил `MAX_JOBS_PER_USER`; задачи в очереди
   учитываются в лимите, пока не завершатся или не завершатся с ошибкой.

### Корректировка цен

- Измените `CREDITS_PER_PAYMENT`, чтобы управлять количеством кредитов за
  успешный платёж в Telegram Stars.
- Измените `CREDITS_PER_GENERATION`, чтобы управлять стоимостью одной заявки на
  генерацию видео.
- После изменения любых значений перезапустите бота, чтобы подхватить новую
  конфигурацию. Существующие записи в базе не меняются, поэтому зафиксируйте
  дату вступления новых цен в силу для поддержки пользователей.

### Работа при сбоях Gemini Veo и деградации производительности

1. Следите за логами на наличие повторяющихся сообщений `Gemini API error` или
   предупреждений `Failed to poll job`.
2. Во время сбоя очередь заданий автоматически повторяет неудачные запросы с
   экспоненциальной паузой. Кредиты автоматически возвращаются для задач, которые
   перешли в состояние `failed` или `errored`.
3. Если сбой затягивается, временно приостановите приём новых заявок, сильно
   увеличив `CREDITS_PER_GENERATION` или отключив команду `/generate` в боевой
   ветке.
4. После восстановления сервиса верните обычные настройки и наблюдайте за
   очередью, пока все ожидания не перейдут в статус `completed`.

### Устранение очередей

1. Проверьте лист `jobs` на записи в состояниях `queued` или `running`
   напрямую в Google Sheets или через любимый клиент.
2. Временно увеличьте `JOBS_CONCURRENCY`, чтобы позволить большему числу воркеров
   обрабатывать отставание. Перезапустите бота для применения изменений.
3. Для задач, застрявших в `processing` без прогресса, переочередьте их,
   обновив статус на `queued`, или удалите и верните кредиты (увеличьте поле
   `credits` в таблице `users`) по необходимости.
4. Убедитесь, что очередь сообщает `Recovered X pending jobs` без ошибок после
   перезапуска.

## Deploy & TLS

- Единое FastAPI-приложение (Telegram вебхук, YooKassa, `/healthz`) запускается на
  `HOST:PORT` (по умолчанию `0.0.0.0:8080`). Настройте reverse proxy (например,
  Nginx или Caddy), который принимает HTTPS-трафик на `PUBLIC_BASE_URL` и
  проксирует запросы к этому порту.
- Сертификаты TLS должны быть действительными, иначе YooKassa не примет
  вебхуки. На тестовом стенде можно использовать бесплатные сертификаты Let's
  Encrypt.
- Не забудьте открыть порт в брандмауэре и разрешить IP-диапазоны YooKassa
  (список сетей приведён в `app_server.py`) или разместите прокси в публичной сети.
- При деплое убедитесь, что переменные окружения совпадают с боевыми ключами и
  доменами, и перезапустите бота после обновления конфигурации.

## Ручные приёмочные тесты

Проведите эти проверки после крупных изменений, чтобы убедиться в корректности
ключевых сценариев:

### Проверка режимов запуска

1. Установите `BOT_MODE=polling` и убедитесь, что бот запускает long polling,
   эндпоинт `/healthz` отвечает `{"ok": true, "mode": "polling"}`, вебхуки YooKassa
   принимаются, а Telegram вебхук удалён.
2. Отправьте `/start` и обычное сообщение — бот должен корректно ответить.
3. Переключите `BOT_MODE=webhook` или запустите `python main.py --mode webhook`.
   При старте бот должен установить вебхук и не запускать polling.
4. Выполните запрос `curl -X POST https://your.domain/tg/webhook -H "X-Telegram-Bot-Api-Secret-Token: <secret>" -d '<валидный апдейт>'`
   и убедитесь, что FastAPI возвращает `200`, а обработчик срабатывает.
5. Завершите процесс и проверьте, что вебхук Telegram удалён.
6. Для YooKassa отправьте тестовый `payment.succeeded` — обработчик должен остаться
   работоспособным.

### Общие сценарии

1. **Onboarding** – отправьте `/start` боту и убедитесь, что приходит приветствие
   и в таблице `users` появляется новая запись.
2. **Проверка баланса** – отправьте `/balance` и убедитесь, что число кредитов
   совпадает со значением в листе `users`.
3. **Отправка промпта** – отправьте `/generate <prompt>` при достаточном количестве
   кредитов и убедитесь, что получено подтверждение постановки в очередь и создана
   запись задачи со статусом `queued`.
4. **Валидация промпта** – отправьте `/generate` без текста и убедитесь, что бот
   отвечает подсказкой по использованию.
5. **Проверка кредитов** – уменьшите количество кредитов пользователя ниже
   `CREDITS_PER_GENERATION` и проверьте, что `/generate` отвечает сообщением о
   нехватке кредитов.
6. **Лимит параллельных задач** – создайте больше задач, чем `MAX_JOBS_PER_USER`,
   и убедитесь, что бот отклоняет новые запросы.
7. **Обработка платежей** – проведите тестовый платёж Telegram Stars и убедитесь,
   что появляется сообщение-подтверждение, а кредиты увеличиваются на
   `CREDITS_PER_PAYMENT`.
8. **Уведомление о завершении** – дождитесь или смоделируйте завершение задачи и
   убедитесь, что бот отправляет сообщение о завершении с ссылкой на скачивание.
9. **Обработка ошибок генерации** – смоделируйте неудачную задачу (вернув `failed`
   от провайдера) и проверьте, что отправляется сообщение об ошибке, а кредиты
   возвращаются.
10. **Устойчивость к перезапускам** – перезапустите бота с невыполненными задачами
    и убедитесь, что они восстанавливаются и продолжают обрабатываться.
11. **Оплата через YooKassa** – выполните `/buy_card`, выберите пакет на 1 кредит
    и оплатите тестовой картой. После вебхука `payment.succeeded` убедитесь, что
    баланс увеличился на соответствующее количество кредитов и отправлено
    уведомление «Зачислено X кредитов. Спасибо!».
12. **Идемпотентность вебхука** – повторно отправьте тот же `payment.succeeded` и
    проверьте, что баланс не изменился повторно, а обработчик вернул HTTP 200.
13. **Отмена платежа** – отмените оплату в кабинете YooKassa и убедитесь, что
    статус в БД становится `canceled`, кредиты не добавляются.
14. **Резервный опрос YooKassa** – отключите вебхуки и убедитесь, что фоновой
    poller обновляет статус `pending`/`waiting_for_capture` до финального в
    течение нескольких минут.
